# Development delivery gates

The development prerelease is held until these actual operations pass:

1. Rules, application/security, real UCI failure and research regression suites.
2. Actual standalone/Joomla browser gameplay, complete terminal game, PGN import,
   bounded analysis, variations, learning, mobile interaction and exact restart.
3. Real administrator package upload/install with no missing files or warnings.
4. Independent MariaDB backup/restore and SQLite backup/restore integrity.
5. Complete source commit, source-bound ZIPs, required files and credential scan.
6. Fresh extracted Python startup/gameplay/UCI/cache/restart/persistence.
7. Fresh extracted Joomla setup with separate site/ports/database and own lifecycle.
8. Repaired prospective relevance experiment, paired tournament and persisted replay.
9. Draft asset inventory and source tag, publication, actual download and SHA256 match.
10. Original DRAGONHYDRA source/process/release and Stockfish identity preservation.

Local evidence retains failed attempts and repaired receipts. No passing test is
inferred from a source implementation, GUI title, executable inventory or version
query. Source and test receipts identify their stage; post-publication download
evidence is necessarily produced after frozen packages are built.

The source build excludes runtime databases, credentials, private browser sessions,
SQL backups, virtual environments and unrelated project files. The Verification
ZIP contains inspectable sanitized test evidence. No native desktop or Setup EXE
is claimed in this preview.
